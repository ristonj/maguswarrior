## Challenges

**Action Item 2 from Epic 1 retro slipped.** The Hero model architecture doc update was agreed on 2026-06-06 but never written. Two weeks and a full epic later, we're heading into Epic 3 (Combat) which directly touches hand and deck mechanics. The doc update is now blocking.

**Commit model is wrong by design.** The `HandView` Commit button was a reasonable placeholder but does not match the game's actual undo model. In play, the explicit Commit tap between "stage a card" and "see the effect" is friction that interrupts the game rhythm. The correct model was never fully articulated until this retro.

**TileStock counts are fictional.** `TileStock(8, 3)` is hardcoded in `PlaceholderMainMenu`, disconnected from the actual tiles placed in `WorldMap`. After revealing `countryside-1`, the HUD reads `Countryside: 7` even though zero further countryside tiles exist to reveal. This is an intentional placeholder — but it's fiction, and it stays fiction until the real tile deck (loading `data/tiles.yaml`, shuffle, draw) is implemented.

**`HexMapView.Initialize` creates polygons once.** Tiles placed at runtime (from a future tile deck) won't render — no polygon is created. This is a known deferral logged in `deferred-work.md`, but it's worth calling out: the tile-drawing story must add a "create polygon on PlaceTile/RevealTile" path or fog hexes will be invisible-but-tappable.

## Key Insights

### 1. The Undo Gate Principle (most important finding of this retro)

The game's undo model has a single, unified rule: **new information revealed = undo gate.**

When an undo gate fires, all pending staged actions commit automatically and the undo stack clears. No button. No manual confirmation. The gate is the commit.

**Non-exhaustive list of undo gates in Mage Knight:**
- Tile reveal (moving to map edge)
- Enemy token flip (engaging in combat)
- Drawing a card mid-turn
- Re-rolling a source die mid-turn
- Refreshing the Advanced Actions or Spells offer row
- Acquiring an Artifact
- Revealing a ruin

The gate fires when the new value/state becomes *visible*, not when the action is declared. (Declaring "I'm entering combat" is not the gate. Flipping the enemy token is.)

A player can undo their way out of combat entirely — including the decision to engage — as long as no enemy token has been flipped.

### 2. Undo gates = save checkpoints

The restoration point for story 3-6 (force-quit mid-combat and restore to exact decision point) is the snapshot written at the last undo gate crossing. The gate mechanism and the checkpoint mechanism are the same event.

### 3. The Commit button goes away entirely

Design decision (John, 2026-06-19): the Commit button is removed. The undo gate is the only commit mechanism. There is no voluntary self-commit. Option (a).

### 4. InputLock-first is a reusable pattern

Any epic that introduces new `async void` Godot signal handlers should begin with a story that establishes the shared infrastructure before feature stories. Epic 2 proved this works.

### 5. Sonnet dev / Opus review split is essential

The model split caught real, ship-blocking bugs every story. On a solo project where John cannot backstop API correctness himself, the Opus review layer is the sole safety net. Never skip it, never run it on Sonnet.

## On-Device Findings (Galaxy S21, 2026-06-19)

Verified on device after manual pass. General behavior confirmed good. One bug found:

**Bug: Move undo blocked after committing a card play.** After committing staged cards via the Commit button, tapping the hero's current hex did not undo the last move (undo was silently blocked). This is the concrete on-device manifestation of the commit model design flaw identified in the retro. The Commit button is acting as an implicit undo gate when it should not be. **Resolution: story 3-0** — removing the Commit button eliminates the trigger entirely. Not a separate story; already captured.

**Zoom/pan not present** — the map renders at a fixed hex size with no pinch-to-zoom or pan. The UX spec lists `pinch (map zoom)` as a v1 gesture requirement. Not Epic 2 scope; flagged for Epic 8 (UI/UX). Note: adding a `Camera2D` will break the current `ToLocal` tap-to-hex math — already tracked in `deferred-work.md`.
