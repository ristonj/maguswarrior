## Challenges

**Re-entrancy is the #1 recurring pattern — 5/7 Epic 1b stories.**

| Story | Issue |
|-------|-------|
| 1b-3 | Commit button not disabled during `ResolveAll` — double-apply |
| 1b-4 | Undo not guarded against `_committing` — undo-during-commit window |
| 1b-6 | `DiscardCard` fires `HandChanged` synchronously before flag flips — wound rows stranded |
| 1b-6 | Open `CardExpanded` in Movement, declare Rest, Play bypasses phase guard |
| 1b-7 | `OnResourceSelected` no re-entrancy guard, no try/finally — overlay stuck on throw |

Root cause: `async void` Godot signal handlers + synchronous C# events (`HandChanged`, `StagingChanged`) + state mutations = re-entrancy hazards. Each instance was patched individually. The structural fix — a centralized `InputLock` — is a new Epic 2 story (see Action Items).

**Hand lives outside GameState.** `DeckManager.Hand` is not in `GameStateSnapshot`. `RestoreSnapshot` restores resource pools but not cards. Staging undo handles the hand side manually via `Unstage` + `ReturnCard`. Rest discards are intentional undo gates. Not a current bug, but becomes a design constraint when mid-combat card plays need full undo.

**UI layout roughness.** Text ran off cards on-device. No wrong information hidden — card names and effect types were readable — but polish is needed. Epic 8 concern, not a rules or logic issue.

**Tests csproj per-file Compile links.** Now 13+ manual `<Compile Include>` entries. Every new effect file needs a manual addition or tests silently skip it. Becoming a maintenance burden.

---

## Key Insights

1. **Re-entrancy is structural, not incidental.** Five instances across seven stories means the per-component `_committing` flag approach doesn't scale. A centralized `InputLock` before Epic 3's combat loop is mandatory.

2. **The model selection split (Sonnet dev / Opus review) works.** Opus found bugs Sonnet missed in its own code every single story. On a project where John can't backstop API correctness himself, the review is the sole safety net — it must run on Opus, always.

3. **`deferred-work.md` is earning its keep.** The 40+ tracked items with context, file references, and "why deferred" reasoning are what make the handoff between stories safe. Without this, each story would re-discover deferred items from scratch.

4. **Rules are a first-class correctness concern.** The Wound/Improvisation catch came from the code reviewer checking the rulebook PDF directly. That's the review doing what it should — not just checking code, but checking code against the game's rules.

## Architectural Decision — Hero Model

**Decision made during retrospective (John, 2026-06-06):**

`Hero` class owns `Hand`, `DrawPile`, `DiscardPile`, `Fame`, `Reputation`, `Units`. `GameState` holds `Hero` as a member. `GameStateSnapshot` will capture `Hero` state alongside turn-scoped pools. `DeckManager` is refactored into or replaced by `Hero` when hero state arrives.

Name is "Hero" — consistent with existing `data/heroes.yaml` and `HeroLoader` in the file placement table. "Player" is a UI concept; "Hero" is the in-game entity matching Mage Knight's domain language.

Turn-scoped resources (Move, Attack, Block, Influence) remain on `GameState` — they reset each turn. Hero state (Hand, Fame, Reputation, Units) persists across turns and belongs on `Hero`.

**Timing:** No action in Epic 2. Design constraint for Epic 3 story planning. Architecture doc update before Epic 3 kickoff.
