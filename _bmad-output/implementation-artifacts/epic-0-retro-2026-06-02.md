## What Went Well

**Architecture foundations held.** `Result<T>`, the pure C# / Godot boundary, the two-constructor `GameState` pattern — all survived Epic 1a unchanged. Getting these right in Epic 0 meant zero rework through the next two epics.

**AOT constraint caught and solved early.** Recognizing that Android IL2CPP breaks reflection-based JSON serialization and solving it with `System.Text.Json` source generators in Story 0-2 was the kind of decision that would have been catastrophic to discover in Epic 3.

**i18n enforced from day one.** Every player-facing string routes through the CSV string table from the first placeholder screen. No debt here.

**Code review caught real bugs every story.** A compile blocker (`ModeFlags.ReadWriteKeepExisting` doesn't exist in Godot 4.6), two high-severity issues in the save system, and a medium all caught before shipping.

**Headless export / adb-from-WSL process.** Discovering how to do most of the build pipeline without requiring the Godot editor GUI on Windows reduced the human-in-the-loop bottleneck significantly.

## Challenges

**The blank screen incident.** The major blocker of Epic 0. A Godot-3 `script=` property in `MainBootstrap.tscn` that Godot 4 silently ignores meant the main scene ran with no code attached. No error, no output — just a grey screen. Device verification for stories 0-2 and 0-3 was blocked for multiple cycles before root cause was found. Fixed in commit 8c06ca2.

*Root cause:* Silent failure with no diagnostic output.
*Systemic fix:* Proactive startup diagnostics before any device-touching story.

**API hallucinations — same model reviewing its own work.** Story 0-2 had a compile blocker because `ModeFlags.ReadWriteKeepExisting` doesn't exist in Godot 4.6. Sonnet wrote it; Sonnet reviewed it without catching it. The code review process eventually caught it, but only because John switched to Opus. Sonnet reviewing its own Godot API calls is the same model catching its own blind spots.

*Fix:* Opus mandatory for all code reviews. context7 for Godot API lookups at write time.

**`project.godot` editor rewrites dropping manual settings.** The Godot editor silently regenerated `project.godot` during import and dropped manually-added `locale/fallback = "en"` and `window/handheld/orientation = 0`. Required detecting and restoring both settings.

*Fix:* After any editor save, verify these two settings are still present.

**Hardware verification deferred too long.** Stories 0-2 and 0-3 both closed with device AC unverified. This meant the blank screen wasn't discovered until both stories were "done" in sprint-status.

*Fix:* Silent failure audit before device stories. Stories should not be marked done with hardware AC outstanding.

---

## Key Insights

1. **Silent failures are the enemy.** The blank screen had no output to diagnose. One `Log.Debug("[Boot]", "script attached, _Ready() running")` at app startup would have made it a one-cycle fix.

2. **Model selection matters for code review.** Opus produces qualitatively stronger reviews for Godot API correctness. On this project, where John can't backstop API errors himself, the code review is the sole safety net. The net must be strong.

3. **John holds Layer 2 (architecture + design decisions), not Layer 3 (API/implementation details).** John understands why async/await, why `Result<T>`, why the C# boundary — well enough to catch drift and push back. That's the right division. He doesn't need to know the exact Godot 4.6 file API.

4. **The architecture foundations from Epic 0 are load-bearing.** They survived Epic 1a unchanged. That's the validation.
